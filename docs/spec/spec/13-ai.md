# 13 — Governed AI use (`YAF.AI`, optional, later release)

> **Release.** `YAF.AI` is not part of YAF 1.0. This file is the design of the package for a later release, kept here so that the 1.0 contracts it builds on (dispatcher, execution context, classification, key rings, retention, the audit chain's sealing) leave room for it. Nothing in 1.0 implements it, references it or reserves a milestone for it; the `DecisionRecord` aggregate of §5 ships together with it.

A service that calls an AI model does so through this package, so that every call is recorded, attributable, bounded and reviewable. The package is off unless referenced; nothing else in YAF depends on it.

It supports obligations that code can support (record-keeping, transparency markers, human oversight records, log retention, robustness guards). It does not classify a system's risk level, does not establish conformity, and cannot make a model accurate or unbiased.

## 1. Shape

```csharp
builder.AddYafAi(ai => ai
    .AddFeature("session-summary", f => f
        .UseChatClient("default")                      // a keyed Microsoft.Extensions.AI IChatClient registered by the app
        .AllowModels("provider/model-id@2026-10")      // allow-list, exact ids
        .Purpose("summarise-session-feedback")
        .RequireHumanApprovalFor(AiEffect.SideEffect)
        .Quota(perTenantPerDay: 500)
        .Retention("P6M")));
```

- Built on `Microsoft.Extensions.AI` abstractions (`IChatClient`, `IEmbeddingGenerator`). The provider SDK is the app's choice and registration.
- Application code injects `IAiGateway` and names a **feature**; it never resolves a chat client directly (analyzer `YAF13001` flags `IChatClient` injected outside composition roots when `YAF.AI` is referenced).

```csharp
public interface IAiGateway
{
    ValueTask<Result<AiResponse<T>>> CompleteAsync<T>(string feature, AiPrompt prompt, CancellationToken ct);
    IAsyncEnumerable<AiChunk> StreamAsync(string feature, AiPrompt prompt, CancellationToken ct);
    ValueTask<Result<Embedding<float>[]>> EmbedAsync(string feature, IReadOnlyList<string> inputs, CancellationToken ct);
}
```

`AiPrompt.From(template).WithData(name, value)`; `AiResponse<T>` has `Value`, `Provenance`, `Usage`, `DecisionId?`. The feature builder also has `.PersonalData(PersonalDataPolicy.Refuse | Pseudonymise | Allow)`.

`AiPrompt` = a versioned template id (`PromptTemplate("session-summary", version: 3)`) + typed variables. Templates live in the service as resources and are part of the approved artefacts (a changed template is a visible diff). System instructions and user/retrieved content are separate channels; retrieved content is always passed as data, never concatenated into instructions.

## 2. What the gateway does on every call

1. **Authorises**: the feature is enabled (`IFeatureFlags`, per tenant kill switch `Ai:Features:<name>:Enabled`), the model is on the allow-list, the tenant's quota has room.
2. **Minimises**: variables are classified; `[SecretData]` is refused; personal data is pseudonymised or removed according to the feature's `PersonalDataPolicy` (`Refuse` default, `Pseudonymise`, `Allow` with justification) before the prompt is built.
3. **Bounds**: input size limit, output token limit, timeout, the standard resilience pipeline, no retries for non-idempotent tool calls.
4. **Calls** the model inside a span following the OpenTelemetry GenAI conventions.
5. **Validates** output: for `CompleteAsync<T>`, strict JSON schema binding to `T`; a mismatch is `ai.output.invalid`, retried at most once with the validation error, then a failed result. Output is never executed, never rendered unencoded, never used as a query or command without validation.
6. **Records** the call (§3) in the same unit of work when one exists, otherwise in its own transaction.
7. **Marks** the result: `AiResponse<T>` carries `AiProvenance` (feature, model, model version, call id, generated-at) which response contracts expose (§4).

Tools (function calling): a feature declares an allow-list of tools; each tool is a YAF request sent through the dispatcher **under the caller's execution context**, so permissions and tenant isolation apply to the model exactly as to the user. A tool whose request is a command is an `AiEffect.SideEffect` and, when the feature says so, is not executed but returned as a pending decision (§5).

## 3. The AI call record

Append-only table `yaf_ai_calls`, written in the caller's transaction and sealed into a hash chain afterwards by the same mechanism as the audit trail (`05-persistence.md`), partitioned by month like it:

| Field | Notes |
|---|---|
| id, time, tenant, actor, initiator, correlation id, trace id | From the execution context |
| feature, purpose | |
| provider, model, model version | As reported by the provider, plus the configured id |
| prompt template id and version | |
| input hash, output hash | SHA-256 of the canonical content |
| input, output | Optional (`Ai:Features:<name>:StoreContent`), encrypted with the subject key when a data subject is known, else the key ring; redacted per classification first |
| parameters | Temperature, max tokens, tool list |
| tool calls | Name, arguments hash, outcome |
| usage | Input and output tokens, latency |
| guardrail verdicts | Size, schema, policy checks and their results |
| outcome | `succeeded`, `invalid_output`, `refused`, `failed`, `quota_exceeded` |
| decision id | Link to a decision record when human oversight applies |

Retention: per feature, with a **floor of six months** that the purge job respects (`Privacy:Retention:AiCalls`); the floor can be raised by profile. Records are covered by erasure through subject-key shredding (hashes remain).

Security events: `ai.model_not_allowed`, `ai.quota_exceeded`, `ai.output_invalid`, `ai.tool_denied`, `ai.kill_switch`, `ai.personal_data_refused`.

## 4. Transparency

- A response contract that contains model output implements `IAiGenerated` (`AiProvenance? Ai { get; }`); the OpenAPI transformer documents it and adds `x-yaf-ai-generated: true` to the operation.
- `YAF.Http` adds the response header `AI-Generated: feature="<name>"` when the request's result is `IAiGenerated`.
- Conversational endpoints declare `.WithAiInteractionNotice()`, which adds an `aiInteraction: true` member to the first response of a session; showing the notice is the client's job.
- Content persisted from model output stores its provenance next to it (`IAiProvenanceMemento`: call id, model, human-reviewed flag); provider-supplied content credentials or watermarks are stored and passed through untouched. Marking generated media is the generating system's responsibility.
- `GET /capabilities` lists AI features with purpose, models and limits (an "AI capability manifest").

## 5. Human oversight

`DecisionRecord` aggregate (to be defined in `YAF.Application.Decisions` in the release that brings `YAF.AI`, so that `YAF.AI` and the privacy coordinator can both use it without depending on each other; its storage mapping goes into a persistence package of its own, as `YAF.Privacy.EfCore` does for `YAF.Privacy`): subject (what is being decided), proposed outcome with provenance, state machine `Proposed → Approved | Overridden | Rejected | Expired`, reviewer principal, reason, timestamps.

- `RequireHumanApprovalFor(AiEffect.SideEffect)` makes the gateway return a pending `DecisionRecord` instead of executing a side-effecting tool; an `ApproveDecision` command (permission flagged `privileged`) executes it under the **reviewer's** context.
- A reviewer can always override or reject; both are recorded. An approval record alone is not human oversight in the regulatory sense — reviewers must be competent and empowered, which is organisational.
- Kill switch: per feature and per tenant, reloadable, effective immediately, recorded.

## 6. Retrieval and embeddings

- A vector store is accessed through `ITenantVectorStore`, which adds the tenant filter to every query and refuses a query without a tenant.
- Indexed documents keep source id and classification; documents classified personal are not indexed unless the feature's policy allows it; erasure removes a subject's vectors (the eraser hook).

## 7. Risk mapping (OWASP Top 10 for LLM applications)

| Risk | Guard |
|---|---|
| Prompt injection | Channel separation; retrieved content as data; output validation; tools run with the caller's permissions |
| Sensitive information disclosure | Classification-driven minimisation before the prompt; no secrets in prompts |
| Supply chain | Model allow-list with exact versions; SBOM |
| Improper output handling | Schema validation; never executed or rendered raw |
| Excessive agency | Tool allow-list; human approval for side effects |
| System prompt leakage | Templates contain no secrets (checked by the template approval test's secret scan) |
| Vector and embedding weaknesses | Tenant-filtered vector access |
| Unbounded consumption | Quotas, token limits, timeouts, rate limits |

## 8. Acceptance criteria

For the release that ships the package. Tests with a fake `IChatClient`:

- Every call produces a record with the fields of §3; the chain verifies; content is absent unless enabled and encrypted when present.
- Model not on the allow-list, disabled feature, exhausted quota → failed result, no provider call, security event.
- Personal data in variables with policy `Refuse` → refused; with `Pseudonymise` → the provider receives no original value.
- Invalid structured output → one repair attempt, then failure.
- A side-effecting tool with approval required returns a pending decision; approving executes it under the reviewer; rejecting does not.
- A tool call cannot read another tenant's data or exceed the caller's permissions.
- Retention purge never deletes a record younger than the floor.
- `IAiGenerated` responses carry the header and the OpenAPI extension.
