# 0005 — Repository skeleton (M0): plan

**Spec** `specs/0000-framework/` (here `docs/spec/`), milestone M0 of `18-build-plan.md` §2. Sections: `01` §1, §4, §6; `17` §1–2, §6, §7 (the gate items); `docs/spec/agents/`; `docs/spec/factory/`; ADR-0029; ADR-0003 (target framework, allow-list); ADR-0018 (test libraries) · **Status** Draft

## Approach

M0 has two halves. **The factory half is done.** Pull requests #1 and #2 installed the kit by reference, and plans 0001–0004 made it work on this machine and unattended. What is left of it is listed under "M0 row, item by item" below: the `ci.yml` checks in the ruleset, the strict policy or merge queue, and the gate trials of `17` §7 that have not been proven. Those are owner steps, not tickets. **The code half has not started.** The repository has no solution, no build settings and no `ci.yml`. This plan builds that half as eleven factory tickets. The factory starts with M0's code instead of M1 (deviation 1).

The shape comes from probes on SDK 11.0.100 ([research](./research.md) §2, §3):

- **T2, one ticket for the solution and the placeholder test.** An empty `YAF.slnx` builds with a warning, and `dotnet test --solution` fails on it. So `global.json`, the root `Directory.Build.props`, `Directory.Packages.props` (central package management), `nuget.config`, `YAF.slnx`, the ignore and attributes files and `tests/Skeleton.Tests` come together. `AnalysisMode` `All` turns on `CA1707`, which forbids the repository's `Method_Scenario_Expected` test names. So T2 also brings a minimal `.editorconfig` with that one suppression.
- **T3: the full `.editorconfig`.** The code style rules of `01` §5 (file-scoped namespaces, `_camelCase` fields, …) and the documented suppression list of `01` §4. A probe project must fail with the style diagnostics (P1).
- **T4: library settings for `src/`.** `src/Directory.Build.props` (XML docs with `CS1591`/`CS1573` as errors, packable, package validation, symbols, the public API and banned API analyzers) and `BannedSymbols.txt`. There is no project in `src/` before M1, so a probe project must fail with `RS0030`, `RS0016` and `CS1591` (P2). Four settings of `01` §4 wait for the milestone that owns them: `IsAotCompatible`/`IsTrimmable` for `YAF.Core` (M1), `PackageValidationBaselineVersion` and `GenerateSBOM` (M14, "package validation baselines, SBOM").
- **T5 then T6: `ci.yml`.** T5 is the instruction validator, a Node script with tests in `.github/scripts/`, which the app can push. T6 is `.github/workflows/ci.yml` with the four jobs the M0 row names: `build-test`, `pr-title`, `security` (secret scan) and `process` (instruction validation). It is the only ticket that changes `.github/workflows/`: **the owner pushes its branch** (AGENTS.md, "Unattended runs").
- **T1 first: let agents run `dotnet`.** The implementer runs in `acceptEdits` mode, and no `dotnet` command is on the allow list in `.claude/settings.json`. In an unattended run every build and test would stop at a prompt. Plan 0003 left this to M0's plan. Until T1 merges, M0's tickets run in an attended session.
- **T7–T10: the hygiene files of `17` §6** that do not exist yet (`SECURITY.md`, `CONTRIBUTING.md`, the bug and feature issue templates with a contact link that sends security reports to private advisories) and the readme's build badge. **T11** writes down the owner's ruleset decision (Q4) in `AGENTS.md` and the runbook once `ci.yml` is required.

Files read to decide: `AGENTS.md`, `docs/spec/agents/AGENTS.root.md`, `docs/spec/agents/AGENTS.nested.md` (`specs/`, `tests/`), `docs/spec/agents/README.md`, `specs/AGENTS.md`, `18` §1, §2, §4, §5, `01`, `17` §1, §2, §6, §7, ADR-0003, ADR-0018 (libraries), ADR-0029 (Enforcement), the kit README ("Install at M0", "Human setup checklist", "Verify before relying on it"), plans 0001–0004, `docs/maintainers/factory-setup.md`, `docs/spec/factory/.github/factory/policy.json`, `plan.mjs`, `classify.mjs`, `lib.mjs`, `test-evidence.sh`, `.github/workflows/factory-gates.yml`, `.github/scripts/sync-references.mjs`, `.github/CODEOWNERS`, `.claude/settings.json`, `.claude/commands/factory-run.md`, the kit's `implementer.md`, `.gitignore`, `README.md`, `LICENSE`.

### Alternatives rejected

| Alternative | Why not |
|---|---|
| Install the code half by hand, as `18` §1 item 2 says | The by-hand rule exists so that the factory does not build its own gates. The gates have been in place since #2, and none of M0's code tickets changes them. Through the factory, every M0 file gets a plan, a ticket, a review and the owner's approval (all are tier high, see Tickets). By hand there is no record and no review |
| One ticket for the whole skeleton | About 600 lines with `.editorconfig` and the validator. It mixes guard files the owner reviews line by line with plain configuration |
| An empty solution first, the test project after | Not warning-free and not testable (research §2) |
| `gitleaks/gitleaks-action` | Needs a licence key secret for an organisation's repository, and forks get no secrets (research §5, Q5) |
| Banning raw SQL, insecure `Random` and ECB through `BannedSymbols.txt` | A symbol ban cannot see how an argument was built or what it is for. It would ban the member everywhere and force suppressions later (hard rule 1). The analyzers that check those cases are used instead (deviation 3) |
| A title check through a third-party action | An inline check against the Conventional Commit types of `yaf-commits-and-pull-requests` is about fifteen lines. It needs no action pin and holds no token |
| All of `17` §2's jobs in M0 (coverage gate, pack, CodeQL, dependency review, actionlint, templates, docs, …) | The M0 row names five checks. The others have nothing to check before code, packages, templates or docs exist (deviation 2) |
| A merge queue now | While the reviews run locally, nobody reports `factory/review` and `factory/doc-review` on a queue commit, so the queue would stall (research §6, Q4) |

## What the tickets contain

- **T2.** `global.json` as in research §1. Root `Directory.Build.props`: the table of `01` §4, without anything that needs a package. `ContinuousIntegrationBuild` is set when `GITHUB_ACTIONS` is `true`. NuGet advisories NU1901–NU1904 stay warnings in local and pull-request builds (excepted from `TreatWarningsAsErrors` through `WarningsNotAsErrors`). They become errors only when `-p:AuditPipeline=true` is passed (`01` §4). The daily `audit.yml` and the `release` job, which set it, come with M14. `Directory.Packages.props`: CPM with transitive pinning, and `xunit.v3`. `nuget.config` as in research §2. `YAF.slnx` made with `dotnet new sln` and `dotnet sln add`. `.gitignore` gets `bin/`, `obj/`, `artifacts/`, `TestResults/` and `*.received.*`. `.gitattributes`: `* text=auto eol=lf`; the index is already LF, so `git add --renormalize .` must change nothing. `.editorconfig`: `root = true` and `CA1707` off for `tests/**.cs` with the reason (Q8 (a)). The pull request needs the owner's `guard-change`. `tests/AGENTS.md`: a pointer file like `specs/AGENTS.md`. `tests/Skeleton.Tests`: one test, `SkeletonTests.Runtime_Version_IsNet11`, which asserts `Environment.Version.Major == 11` with xUnit's `Assert`. The suppression list is under one heading, each entry with its reason. The list holds only what the build of T2 plus the probe of P1 need. T3 does not reformat files other than `tests/Skeleton.Tests`.
- **T4.** The banned list of `01` §4 as symbols: `DateTime.Now`/`UtcNow`, `DateTimeOffset.Now`/`UtcNow`, `Guid.NewGuid()`, `System.Console`, `Environment.GetEnvironmentVariable`, `MD5`, `SHA1`, `DES`, `TripleDES`, `RC2`, `EntityFrameworkQueryableExtensions.IgnoreQueryFilters`, `LoggerExtensions.Log*`, `UseInMemoryDatabase`, and the one-shot ECB methods `SymmetricAlgorithm.EncryptEcb`/`DecryptEcb`. `CA5358` does not see those methods (research §3). Each entry has a message that names the replacement. An entry for a method needs its full parameter list: written without one, it matched nothing in the probe (research §3). So T4 lists every overload, for example all the `LoggerExtensions.Log*` overloads, taken from the package's reference documentation for the version in `Directory.Packages.props`. Entries for packages not yet referenced cause no diagnostic. `src/AGENTS.md`: a pointer file.
- **T5.** `.github/scripts/validate-instructions.mjs` (Node 22, no dependencies, reuses `frontMatter` from `sync-references.mjs`) and its tests. It checks, from `17` §2 `process`:

## Deviations from the specification

1. **M0 is not installed by hand** (`18` §1 item 2). Its code half runs as factory tickets. The factory half was installed by hand (#2), as the rule asks. Why: see Alternatives. The gates the rule protects are untouched, and every ticket waits for the owner. Accepted by the owner (Q1). The amendment of `18` §1 item 2 follows in a spec pull request of its own (decision log, follow-up).
2. **`ci.yml` in M0 is a subset of `17` §2.** The four jobs are those the M0 row names, under `17` §2's names. Left out for now: the `build-test` steps for the `#if NET` check, the coverage report and gate, `dotnet pack` and the uploads, and the jobs `generated-in-sync`, `ef-model`, `templates`, `sample-on-packages`, `docs`, `transports`. Also the `security` steps `dependency-review`, CodeQL and actionlint. Why: nothing for them to check yet. Each comes with the plan of the first milestone that gives it something (M14 at the latest, `18` §2).
3. **Part of the banned list is enforced by analyzers, not `BannedSymbols.txt`** (`01` §4). Insecure `Random` is caught by `CA5394`. ECB set through `CipherMode.ECB` is caught by `CA5358`. Both fired as build errors under `AnalysisMode` `All` on SDK 11.0.100 (research §3, executed). The one-shot `EncryptEcb`/`DecryptEcb` methods, which `CA5358` misses, are banned as symbols. Interpolated raw SQL is left to EF Core's analyzer from M3, whose rule id M3's plan verifies. `IgnoreQueryFilters` is banned in all of `src` until M3 exempts `YAF.Persistence.EfCore`. Why: a symbol ban cannot see how an argument was built or what it is for.
4. **Folder `0005-repository-skeleton`, not `0001-repository-skeleton`** (`18` §5). Why: 0001–0004 are the factory's plans.
5. **Trial 2 after M1 starts** (`18` §1 item 2). Accepted by the owner (Q6).
6. **The docs tickets are not verified by the docs build** (ADR-0025, Tickets table). T7, T8, T10 and T11 use the greps in their Verify cells. Why: `docfx.json` comes with M14 (plan 0001 deviation 3 did the same).
7. **No merge queue, and strict status checks stay off** (`17` §1 "Merges go through the merge queue"; the M0 row's "branch rules with the required checks and the merge queue"). Accepted by the owner (Q4). Why: research §6. While the reviews run locally, a queue would stall. Strict checks would dismiss approvals and repeat reviews. It is a temporary departure: it ends when the reviews move back to CI (AGENTS.md, "Model reviews run locally"). The spec text stays.

The quick start comes with M13, when `dotnet new` templates exist. Coverage, release and docs badges come with M14, which makes them. Why: none of these exists yet. Spec text: none.
